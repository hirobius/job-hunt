# Job sources we do not read yet: research and ranking (2026-11)

Researched 2026-11-17 for Adrian's ask: as many new job sources for roleflame as possible, in one
pass. Builds on `ds-job-sources.md` (2026-10-28) and `job-sources.md` (2026-10-15); the sources
those already cover, and which the app reads, are not repeated here. Another session is widening
titles, contract roles, Adzuna, Jooble and `boards.json` at the same time, so those are out of scope.

## How this was checked (read first)

- **No source page could be read live from the build container.** The network blocked every job
  host (curl: proxy 403; WebFetch: host not allowed). Every finding comes from about 70 web search
  results. Each row says how sure it is:
  - **V-own**: a search result quoted the source's own docs or terms page.
  - **V-2nd**: only secondary pages (often vendors that sell this data).
  - **K**: from prior knowledge, not seen in this pass.
- So every adapter built here is marked **UNVERIFIED LIVE** in its header (as Jooble and TheirStack
  were), reads fields defensively (`src/tracks/feeds/shape.ts`: a renamed field drops a row, never
  stores a wrong one), and is pinned with a recorded fixture. Its first live run should be checked in
  `sync_log` and its fixture replaced with a real answer.
- **Yield** = design-systems or design-engineer postings expected at one time, after our title rule
  (`dsRole.ts`). Board size × the share of DS titles (0.1–0.5% for general tech boards). Order of
  magnitude only.
- **Effort**: S = under a day, M = 1–3 days, L = a week or more.

## Action needed on a source we already read

### The two sources the coordinator added

- **Firecrawl job tools** (https://alexandria.firecrawl.dev/go/jobtools). Firecrawl's "Alexandria"
  data layer reads job boards and career pages on the major ATSs and claims 7M+ roles posted in the
  last 30 days (firecrawl.dev/blog/job-search-tools-chatgpt-claude, V-2nd). It needs a Firecrawl API
  key and spends credits; the per-tool credit cost is listed at alexandria.firecrawl.dev/categories/jobs,
  which the container could not read. Firecrawl's general search is 2 credits per 10 results
  (docs.firecrawl.dev/billing). Yield could be high, but its source is the same ATS boards the
  scan rotation already reads, so its value is discovery of boards we do not have. **Verdict: Maybe
  (paid)** — worth a trial as a fifth x-ray provider (keep only the board slug) once Adrian has read
  its terms and the price per call.
- **"Live tracker of tech layoffs and 90K+ open roles"** (linked from
  archive.codenewsletter.ai/2120157869232537650). The page could not be read from the container and
  search did not name the tracker. The best match is **TrueUp** (trueup.io: a layoffs tracker plus
  open roles at tech companies; 67,000+ software roles reported in 2026). TrueUp has no public API
  found, and its listings come from company career pages we can reach directly. **Verdict: Link only**
  until its terms are read; Adrian can confirm which tracker the newsletter meant.

### Adapter specs for every "Build"

Each adapter returns roleflame's posting shape (title, company, location or remote, url, posted date, description, source).
Mark: (V) field names seen in a snippet of the docs; (K) expected, so log the raw first response and fix the mapping.

### B1. Workable meta-search

- `GET https://jobs.workable.com/api/v1/jobs?query=<term>&workplace=remote&pageToken=<token>` (also takes `location`, `employmentType`, `dayRange`).
- Envelope: `jobs[]`, `nextPageToken` (V); `totalSize` (K).
- Job (K, from scraper outputs): `id, title, url, created, updated, workplace ("remote"|"hybrid"|"on_site"), employmentType, department,
locations[{city, subregion, countryName}], company{id, title, url, website, image}, description` (HTML).
- Dedupe: `company.url` or `company.title` + title through `roleKey`. A posting's company is on Workable, so Save can follow
  `apply.workable.com/<slug>` as a board.
- Server-side (CORS unknown). Run one query per related title ("design system", "design technologist", "design engineer").

### B2. Common Crawl CDX slug discovery (plus Wayback)

- `GET https://index.commoncrawl.org/collinfo.json` → take the newest 2–3 `cdx-api` URLs.
- For each ATS host pattern: `GET <cdx-api>?url=jobs.ashbyhq.com/*&output=json&fl=url&filter=status:200` (path ATSs: Ashby,
  Greenhouse `boards.greenhouse.io/*` and `job-boards.greenhouse.io/*`, Lever `jobs.lever.co/*`, SmartRecruiters `jobs.smartrecruiters.com/*`,
  Polymer `jobs.polymer.co/*`, JobScore `careers.jobscore.com/jobs/*`, Gem, Pinpoint, Rippling…). For subdomain ATSs:
  `url=*.recruitee.com&matchType=domain` (Recruitee, BambooHR, Breezy, Personio `jobs.personio.de`, Teamtailor, Workable
  `apply.workable.com/*`, Manatal `careers-page.com/*`).
- Each NDJSON line is `{urlkey, timestamp, url, mime, status, digest, length, filename, offset}`. Take the first path segment or
  subdomain as the slug, keep unique ones, check each through the ATS's own public API, then keep the companies whose live board has a
  design-system title (this extends `companyDiscovery`; store only the slug).
- Batch job (monthly), with pacing for 429/503 (`tracks/retry.ts`).

### B3. Get on Board

- `GET https://www.getonbrd.com/api/v0/search/jobs?query=<term>&per_page=100&page=<n>&expand=["company"]`
- JSON:API style (K): `data[{id, type:"job", attributes{title, description, projects, functions, benefits, remote, remote_modality,
remote_zone, countries[], seniority{data{id}}, min_salary, max_salary, published_at (epoch), category_name, company{data{id,
attributes{name, logo, web}}}}, links{public_url}}]`, `meta{page, per_page, total_pages}`.
- Link = `links.public_url`. Browser CORS unknown, so read it server-side first.

### B4. 4dayweek.io

- `GET https://4dayweek.io/api/v2/jobs?page=<n>&limit=100` (filters such as schedule) → `{data[], page, limit, total, has_more}` (V).
- Job fields (K; take them from https://4dayweek.io/openapi.yaml): `slug, title, company{name, logo, url}, location, remote / remote_type,
salary_min, salary_max, currency, posted_at, url, description`.
- Show "via 4dayweek.io" with a link (required). Respect `max-age=60`.

### B5. RemoteJobs.org

- `GET https://remotejobs.org/api/v1/jobs?search=<term>&limit=50&offset=<n>`
- Fields (V: ISO posting timestamp, HTML description with an appended apply link; K: `id, title, company, location, url, apply_url,
tags, posted_at`).
- Show a visible "via RemoteJobs.org" link. Keep the apply link unchanged. Sanitize the HTML (`PostingDescription` already sanitizes).

### B6. Jobgether

- `GET https://jobgether.com/api/v1/jobs?keyword=<term>&location=<loc>` (25 per page; full spec at https://jobgether.com/openapi.json).
- Fields (K; take them from openapi.json): `id, title, company{name, logo}, location / remote, posted_at, url` (the Jobgether offer page).
- Its URLs point at Jobgether, so give it a low `sourceRank`: a company-board copy of the same role wins in `dedupeRoles`.

### B7. Hacker News jobstories

- `GET https://hacker-news.firebaseio.com/v0/jobstories.json` → `number[]` (≤200).
- `GET https://hacker-news.firebaseio.com/v0/item/{id}.json` → `{id, type:"job", by, time (unix), title, url?, text? (HTML), score}` (K, stable).
- The title is usually "Company (YC S24) is hiring a Design Engineer"; parse the company from before "(YC" or "is hiring". The link is
  `url`, or `https://news.ycombinator.com/item?id={id}` when there is no `url`. Firebase sends CORS headers, so a browser read is possible
  (add `hacker-news.firebaseio.com` to the CSP and `legal.ts`).

### B8. Polymer

- `GET https://api.polymer.co/v1/hire/organizations/{slug}/jobs` → `{items[], meta{…pagination}}` (V);
  `GET https://api.polymer.co/v1/hire/jobs/{id}`.
- Item (K; February 2026 changelog: description, location, salary, public post URL, remote restrictions): `id, title, location, remote / remote_restriction,
salary, description, job_post_url / public_url, published_at`.
- Add as `BOARD_KINDS` kind `polymer`, fixed host `api.polymer.co`.

### B9. JobScore

- `GET https://careers.jobscore.com/jobs/{company}/feed.json` (or `.xml`).
- Fields (K): `jobs[{id, title, department, city, state, country, location, job_type, remote?, description (HTML), detail_url,
apply_url, opened_date}]`.
- Poll at most once an hour (JobScore's stated limit).

### B10. Manatal

- `GET https://api.careers-page.com/open/v1/career-pages/{client_slug}/job-posts?page=<n>` (also check `/career-page/{client_slug}/jobs/`).
- Fields (K, DRF-style): `count, next, previous, results[{id, hash, position_name, description, city, state, country, address,
is_remote, created_at, salary_min, salary_max, currency}]`. Posting URL (K): `https://www.careers-page.com/{client_slug}/job/{hash}`.

### B11. Comeet

- `GET https://www.comeet.co/careers-api/2.0/company/{uid}/positions?token={token}&details=true`
- The response is a JSON array of position objects (V: "address the position data as a dictionary"). Fields (K, from the position model):
  `uid, name, department, employment_type, experience_level, workplace_type, location{name, city, country, is_remote},
url_comeet_hosted_page, url_active_page, url_detected_page, position_url (API url), time_updated, details[{name, value, order}]`.
- uid and token: read them once from the company's public Comeet careers page (where `COMPANY_DATA` is embedded), and store both in Sources.
  Server-side only (no SPA support; IP throttling).

### B12. USAJOBS

- `GET https://data.usajobs.gov/api/search?Keyword=<term>&ResultsPerPage=500&Page=<n>` with headers `Host: data.usajobs.gov`,
  `User-Agent: <registered email>` (secret), `Authorization-Key: <key>` (secret).
- Fields (K, long-standing): `SearchResult{SearchResultCount, SearchResultCountAll, SearchResultItems[{MatchedObjectId,
MatchedObjectDescriptor{PositionTitle, PositionURI, ApplyURI[], OrganizationName, DepartmentName, PositionLocationDisplay,
PositionLocation[], PublicationStartDate, ApplicationCloseDate, PositionRemuneration[], UserArea{Details{JobSummary,
TeleworkEligible, RemoteIndicator}}}}]}}`.
- `RemoteIndicator` / `TeleworkEligible` feed `classifyRemote`. Server only; keep the key and email out of the repo.

### B13. Findwork.dev

- `GET https://findwork.dev/api/jobs/?search=<term>&remote=true&page=<n>` with header `Authorization: Token <key>`.
- Fields (K): `count, next, previous, results[{id, role, company_name, company_num_employees, employment_type, location, remote, logo,
url, text (HTML), date_posted, keywords[], source}]`.
- Read the findwork.dev terms before shipping.

### B14. Exa / Tavily x-ray (discovery only)

- Exa (K): `POST https://api.exa.ai/search` with header `x-api-key`, body `{"query":"\"design system\" engineer job","includeDomains":["jobs.ashbyhq.com","boards.greenhouse.io","job-boards.greenhouse.io","jobs.lever.co","apply.workable.com"],"numResults":100,"startPublishedDate":"<30d ago>"}`
  → `results[{url, title, publishedDate, id}]`.
- Tavily (K): `POST https://api.tavily.com/search` with `Authorization: Bearer <key>`, body `{"query":"…","include_domains":[…],"max_results":20}` → `results[{url, title, content, score}]`.
- Keep only `(ATS kind, slug)` parsed from `url`. Each slug then goes through B2's check. Spend at most a few hundred queries a month.
