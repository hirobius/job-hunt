Simplify RoleForge

Spec, 2026-10-28. Draft for Adrian's pick: no code changes yet. Branch claude/rf-simplify-spec.

Recommendation in one breath. One home page, Today, with three buttons: Review new (one card at a time: Save or Skip), Apply (Apply mode as it is) and Follow up. One Find box takes anything you paste: a job link, a company, a board or a title. Everything you follow is one Sources list; one Search profile replaces tracks; one Feed turns sources into cards, from the browser when signed out and from the server sync when signed in. About 14k lines (40% of the app) go. You lose multiple tracks, the curated tile boards, GitHub/YC/Adele discovery, Calibrate's knobs and SAM.gov.

1. The problem in numbers

  • 11 ways to find a job and 8 ways to find or keep a company, spread over two tabs, two secondary views, a Refine disclosure, a Calibrate disclosure and Manage track.
  • 13 synced fields in the blob (v11), plus 3 curation tables, plus 4 server tables that were never deployed.
  • Companies is three different things: watched board tiles, outreach targets and dream companies, each with its own store, plus a fourth derived "Company page".
  • Filtering is four overlapping layers: title filter, must include (with related titles), Calibrate (leave-out, level, pay) and the track scorer, which replaces some of the others on one track only.
  • Discovery code is about 16k of the app's 35.6k lines (non-test).

3. Design A: Server inbox

backend-deepsigned-in only

The server does the finding, ranking and remembering. One sources table (boards, companies, feeds, searches) feeds one ranked Inbox (the postings table), scored by sync-postings twice a day. One profile row replaces tracks. The client is thin and learns three calls:

useInbox()           → queue, review, sources
find(input)          → board | company | search | job
triage(id, save|skip|undo)

Deletes: all client discovery (Discover, Companies, Live postings, src/feed/ fetching, HN/Remotive/SAM sources, curation, tracks). CSP shrinks to Supabase only. About −15k source lines.

Migration: watched tiles, dreams, targets and saved searches move to sources; the active track's titles, must include, location and mode become profile. Undeployed migrations are rewritten in place. Blob v12 keeps jobs, documents, kit, trash.

Risks: (1) no discovery at all when signed out; (2) everything rests on an edge function that has never run (bundling, Ashby time limits, boards blocking server IPs); (3) generic ranking for non-design profiles; (4) abuse and cost of user-entered server fetches; legal.ts needs re-approval.

4. Design B: One list, client-first

flexibleworks signed out

The Pipeline is home. A new Status, New, sits before Saved: Find writes results into the same Job list. Every feeder (boards, dreams, targets, tiles, HN, SAM) becomes one Source in one synced store; one app-wide Filter replaces titles, sweep, must include, Calibrate. A PostingReader seam has two adapters: the browser (today's fetchFeed) and the server (postings rows).

Deletes: Discover, Companies, Live postings UI, tiles and curation, tracks, sweep, saved searches. Keeps every source and probe behind the seam. About −10k lines, +2.2k new.

Migration: tiles, dreams, targets become Sources (tag = old group); all tracks' titles merge into one Filter; set-aside tiles become dismissed fingerprints. New jobs ride in a separate found field so old clients never turn them into Saved.

Risks: (1) New jobs bury the real pipeline (needs caps and auto-expiry); (2) blob size; (3) no forward guard today: an older tab rewrites the blob at v11 and drops new fields; (4) one Filter for all hunts.

5. Design C: Today deck

common case first10-minute day

Home is Today: three counts in a fixed order, each opening a one-card-at-a-time walk. One Search profile per account (titles, must include, leave out, location, mode). Companies are followed automatically when you save one of their jobs. One Feed module with two adapters (server signed in, browser signed out). Everything else sits under More.

useDeck()  → card, left, save(), skip(), notThisCompany(), undo()
compileProfile(profile) → scorer config   // shared with the edge function
today(jobs, deckLeft, now) → review, apply, followUp

Deletes: Discover, Companies, Live postings, Find boards, GitHub, YC, Adele, ATS and big-board links, sweep, Calibrate, tracks, curation, Contracts. About −14k source lines, −11k test lines, +1.5k new.

Migration: blob v12 adds profile, companies, decided. Profile comes from the scored track (else the busiest). Companies = union of watched boards, dreams, targets with a board, and boards of saved jobs. Evidence becomes a Note document. "Download old setup" offered once.

Risks: (1) several tracks flatten into one; (2) empty deck on day one; (3) the edge function reads the blob's shape; (4) profile quality outside design systems.

7. Recommendation: C, with B's Sources and A's Find box

  1. Home = Today (C): Review new, Apply, Follow up. The Pipeline becomes Jobs under More, unchanged inside.
  2. One Find box (A) at the top of Today. Paste anything: a job link saves a Job (works signed out, replaces the separate quick-add form); a board or company becomes a Source; words update the Search profile's titles.
  3. One Sources list (B) in the synced blob, not a server table: boards, followed companies (with or without a board), and the two keyless feeds (HN, Remotive). Saving a job follows its company (C). Dreams = a star on a Source.
  4. One Search profile (C): titles, must include, leave out, location, mode. The design-systems scorer stays as the profile's tuned config. Stored as profiles[] with one entry, so a second hunt can come back later without a migration.
  5. One Feed with two adapters: the browser (today's fetchFeed, signed out) and the server (postings, signed in). sync-postings reads Sources and the profile from the blob, so there is one source of truth and watched_companies / skips are never deployed.

Why this mix. C is the only design whose home is Adrian's three controls; its deck makes "keep it pushing" a 10-minute habit instead of a list to scan. B's single Sources store is what makes "companies are a property of jobs" true: one place, one shape. A's paste-anything Find box removes four entry points (Add a company, Check a list, Add job, Watch a company) with one. A's server-only stance is rejected: it would turn off discovery for signed-out users and bet everything on a function that has never run.

The data shape after:

blob v12
  jobs, documents, kit, trash, copydeck (legacy)   kept
  profiles[1]   titles, mustInclude, leaveOut, location, mode
  sources[]     { kind: board|company|feed, ref, label, star? }
  decided[]     { id, verdict, at }   newest 3,000
server
  tracker (blob)   postings   sync_log      // nothing else

Migration from v11 (one-time, after sync settles, like SnippetMigration):

  • Profile from the scored track, else the track with most saved jobs. Other tracks' titles are listed in the notice, not merged.
  • Sources = watched-board tiles + dreams (starred) + targets + boards of saved jobs, deduped by company key. GitHub-only targets keep their website as a company Source.
  • Set-aside tiles and saved jobs seed decided. Evidence text becomes a Note document.
  • Non-board tiles (Apply now sections, search links) are offered once as a "Download your links (.txt)" file, then dropped.
  • Dropped: filters, sweeps, modes, targets, dreams, mustInclude, triage, evidence (after conversion). Curation tables frozen, dropped 30 days later.
  • Before any of this: a forward guard. Today an older tab can rewrite the blob at v11 and silently drop new fields.

8. Slice plan

Each slice ships on its own and leaves the app working. Nothing is deleted until the replacement has been used for a week.

  1. Sync forward guard. A tab that reads a newer blob version stops pushing and shows "Reload to continue".
  2. Today home. today.ts read model and a three-section home; Pipeline becomes Jobs under More. Nothing removed.
  3. One Find box. Paste a job link (save), a board or company (follow), or words (titles). Replaces Add job, Add a company and Watch a company as entry points; old screens stay.
  4. Blob v12: profiles, sources, decided + migration. One-time move from v11 with the links download and a notice. Old fields still read.
  5. Feed module + Review deck (browser adapter). Save, Skip, Not this company over fetchFeed; saving follows the company. Works signed out.
  6. Server adapter. sync-postings reads sources and profile from the blob; watched_companies and skips removed from the undeployed migrations; deploy and seed check (Adrian runs the deploy steps).
  7. Onboarding = profile form. Title + location, starter companies followed, deck opens.
  8. Delete Companies, Discover and tracks. Live postings UI, Companies, Find boards, GitHub, YC, Adele, ATS links, Calibrate, sweep, curation, Contracts. CSP and legal.ts shrink (wording needs Adrian's re-approval).
  9. Cleanup. Stop reading v11 fields, drop curation tables, rewrite CLAUDE.md, CONTEXT.md, add an ADR.

9. What Adrian loses, and why it's worth it

  • More than one track. One profile at a time (switchable later via profiles[]). Contracts and the trades boards go.
  • Curated tile boards (Apply now sections, Manage track). Offered as a links file once.
  • Hunting tools: GitHub org search, YC batches and type-ahead, Adele seed, Check a list of 500, ATS Google search and Big job boards.
  • Calibrate's knobs: pay floor, level, related titles, sweep chips, saved searches, "N hidden by" counts. Leave out and must include stay in the profile.
  • Browsing all postings as one long list. The deck is one card at a time; Jobs under More is still a list.

Why it's worth it. Every one of these was built for a real need, but together they make the first question "which of 19 tools do I use?" instead of "what's next?". The three things that actually move a hunt forward (look at new openings, apply, follow up) are already the best-built parts of the app; this spec puts them on the front page and hides nothing they need. The cut is about 40% of the code and 8 of the 13 synced fields, which also makes every later change cheaper and the sync safer. The tuned design-systems scorer survives as the profile's config, so Adrian's own results should not get worse.
